# Hana 远程访问 · 产品文档（交接版）

版本对应：应用 `hana-remote-access` v1.0.1（安装包 `dist/app-hana-remote-access-1.0.1.zip`）
最后核对：2026-10-08，作者侧本机实测。宿主 HanaAgent 1.0.6-beta。

## 1. 这是什么

让一台**只监听本机**的 HanaAgent，通过用户自己的公网入口（NAS 反向代理 / 端口转发）被手机和另一台电脑使用；配置、启停、扫码配对、设备管理全部收在 **HanaAgent 的设置弹窗里**，不需要再开一个面板网页。

- 形态：HanaAgent v2 应用（`manifestVersion:2`），随包自带网关数据面代码与离线 SDK。
- 交付物：一个 zip，别人拿到就能装。
- 不是：不是云服务、不做穿透、不托管账号、不代管证书。公网入口由用户自己准备。

## 2. 目标用户与使用场景

| 用户 | 场景 | 关注点 |
| --- | --- | --- |
| 自己（重度） | 出门用手机连家里/公司那台 HanaAgent | 扫码即用、不掉线、不用每次重扫 |
| 朋友（转发安装） | 自己有 NAS + DDNS，想复刻同样体验 | 一个 zip 装完，配置项看得懂，权限说明白 |

## 3. 用户可见流程

1. 安装：市场 → 已安装 → 「安装…」→ 选 zip → 确认卡核对 3 项能力 → 确认。
2. 打开「设置 → 远程访问」（左侧标签页标题：**远程访问**）。
3. 第 1 步 配置：公网地址、网关端口（默认 19388）、HanaAgent 端口（31787）、允许的 Host、扫码落地页、配对钥匙权限、名册上限、名册目录、日志开关、启用开关 → 「保存并重载」。
4. 第 2 步 配对：「生成配对二维码」→ 页面内画二维码 + 可复制的配对链接与令牌 + 有效期倒计时。手机浏览器扫码 → 直接落到 pad 版界面并处于已登录状态。
5. 第 3 步 名册：列出已配对设备（在线/离线、最近活动、设备短 id），支持单台「取消配对」、「作废当前二维码」（只作废令牌不动名册）、「全部解除配对」（会吊销宿主侧凭证，需重扫）。
6. 第 4/5 步：一键体检（7 项）、运行日志尾部。

外部前提（应用管不到，必须在文档里告诉用户）：HanaAgent 开「允许局域网设备」；NAS 反代把公网端口指向本机 19388；建议用防火墙把宿主的 31787 限制为本机可访问。

## 4. 决策记录（为什么长这样，改动前必读）

| 决策 | 现状 | 理由 |
| --- | --- | --- |
| 扫码落地页默认 `pad`，不是 `mobile` | 保持 | HanaAgent 自身 `/mobile/` 客户端有缺陷：输入所有权标志 `inputDraftVerified` 从不置位 → 新建会话的请求在发出前就被前端拦下（详见 `docs/技术文档.md` §9）。`/pad/` 不受影响 |
| pad 首次要输一次本地账号密码 | 保持 | pad 闸门要求 12 项 scope（额外含 `tools.run`+`plugins.use`）；宿主把设备钥匙硬上限钉在 10 项，只有账号会话给得出 12 项。不是本应用的取舍 |
| 配对钥匙默认 `full`（一律桌面钥匙） | 保持 | mobile 钥匙只有 4 项 scope，宿主多个路由（如 `/api/agents`）会 403 `insufficient_scope` |
| 名册目录可与旧独立网关共用 | 支持（填 `dataDir`） | 沿用 `devices.json` 就不必重扫；留空用应用自己的数据目录 |
| 名册满时**拒绝**新配对 | 保持 | 早期实现是静默淘汰最旧设备，实测会把真机挤下线 |
| 不申请 `app/ui.clipboard-write` | 保持 | 扩权限会弹确认卡；改为剪贴板失败时降级为「选中文本 + 提示 Ctrl+C」 |
| 面板不再作为独立网页暴露 | 保持 | 用户明确要求「成为配置远程连接的一个步骤」。`/panel` 仍保留在网关里（仅回环可达），作为应急后门 |

## 5. 验收标准（每次迭代都要能复述并跑通）

1. 设置弹窗里能看到「远程访问」标签页，且页面显示的是**真实状态**（宿主登记 `settingsContribution.title` 存在）。
2. 「生成配对二维码」出图 + 出链接；手机扫码后**不需要任何手工登录**即可看到会话列表（pad 首次输密码属宿主限制）。
3. 手机在新链路上可用：`/api/sessions` 200、`POST /api/ws-ticket` 200、`GET /ws` → **101**（WebSocket 必须能穿透，否则表现为无限重连 + 「连接尚未确认」）。
4. 未配对流量被拒（401 `unpaired`），伪造 Host 被拒（403）。
5. 名册与配置在应用重载 / 宿主重启后保持不变（不需要重扫）。
6. 安装包 `validate-app.mjs --archive` 0 error，且包内不含作者域名、内网 IP、用户名、任何令牌。

## 6. 已知问题登记（未修，按优先级）

| # | 现象 | 归属 | 说明 / 处置 |
| --- | --- | --- | --- |
| 1 | `/mobile/` 无法新建会话 | HanaAgent 上游缺陷 | 已定位到 `MobileApp-*.js` 裸 `setState` 绕过 `YR()`；等作者修，修好后把 `landingSurface` 改回 `auto` |
| 2 | pad 需要账号密码 | HanaAgent 权限模型 | 无法用配置绕过；如要免密只能等上游放宽 pad 闸门或允许铸 12 项 scope 钥匙 |
| 3 | 宿主侧遗留 12 条 `active` 设备凭证（多为探针死钥匙） | 本机卫生 | 需要清单化清理，未动 |
| 4 | 体检里「已配对设备」依赖服务在跑 | 本应用 | 网关停了时该项显示 NO，属预期 |
| 5 | 面板 `/panel` 与设置页两套 UI | 本应用 | 面板已降级为应急后门，长期看可删 |

## 7. 发布 / 交接动作

- 改完源码 → 打包 → 校验 → 刷新安装目录 → 重载应用（**能力扩张会弹确认卡，不要偷偷 API 确认**）→ 跑作者工作区里的 `app-check.mjs` 与 `gw-through-app.mjs`（未随包发布）；仓库内任何人都能复现的是设置页「一键体检」（`routes/doctor`）。命令见技术文档 §7。
- 版本号只在 `manifest.json` 里改；`dist/` 下 zip 名由打包器按 `id-version` 生成。
- 转发给别人之前：**必须**再查一次包内是否残留个人信息（技术文档 §10 的检查命令）。
